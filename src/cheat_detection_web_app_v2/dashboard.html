Pro Tips for a Smooth Experience

  • Dedicated GPU: If using "Large" or "Medium" AI models, a dedicated GPU (RTX series) ensures zero lag.
  • Camera Setup: Place the camera 60-100cm away from the student. 720p resolution is the "sweet spot" for accuracy vs speed.
  • Lighting: Ensure front-facing light. Backlighting (windows behind the student) can cause face recognition to fail.
  • Browser: Use Google Chrome or Microsoft Edge for the best WebGL and Camera API performance.

Face Registration & Recognition

How the system identifies students and manages their biometric signatures.

The Registration Process

To enable automatic student identification, you must first register their faces in the system:

  1. Navigate to the Students page from the sidebar.
  2. Click the Register Student button to open the capture modal.
  3. Enter a unique Student ID and the student's Full Name.
  4. Position the student in front of the camera and click Capture Photo.
  5. Click Submit Registration to finalize.

How it Works (AI Tech)

  • Biometric Embeddings: The system uses ArcFace (99.4% accuracy) to convert facial features into a mathematical vector.
  • Privacy First: While thumbnails are kept for proctor reference, identification uses "embeddings" – high-dimensional numbers that are secure and efficient.
  • Instant Matching: During an exam, the AI takes a snapshot of the person's face periodically and calculates its signature to find the closest match in the database.

Tips for Best Results

Tip: For registration, ensure the student is looking directly at the camera with stable lighting. Avoid heavy shadows during the initial capture.

  • One student = One entry. The system handles glasses and minor hairstyle changes automatically.
  • If identification consistently fails, delete the student record and re-register with better lighting.

Proctor Guide

Daily operations: monitoring, alert review, and evidence handling.

Monitor Workspace

  • Live Feed: Real-time camera stream with AI overlays.
  • Alert Queue: New alerts appear with score, reason, and timestamp.
  • Session Status: Timer, device status, and pipeline indicators.

Start & Stop Sessions

  1. Enter an exam/session name.
  2. Click Start Pipeline and wait for live feed.
  3. Monitor alerts in real time.
  4. Click Stop Pipeline when the session ends.

Tip: Clear or confirm pending alerts before ending a session.

Alert Review Flow

  1. Select an alert card to open evidence.
  2. Zoom evidence and check AI reasons.
  3. Confirm or decline the alert.
  4. If confirming, add student ID/name and optional notes.

Declining does not require student info, confirming does.

History & Evidence

  • Filter by date, status, or severity.
  • Open any card to review evidence timeline.
  • Export evidence for disciplinary or audit reports.

Best Practice Checklist

  • Test camera and lighting before the exam.
  • Keep the camera angle stable and wide.
  • Review alerts promptly.
  • Add clear notes for every confirmed case.

Administrator Guide

Configuration, user management, and system tuning.

Detection Configuration

  • YOLO v11 Models: nano, small, medium, large.
  • Confidence Threshold: Lower = more detections, higher = fewer false positives.
  • Image Processing Size: Higher resolution = better accuracy, more compute.
  • Device: GPU recommended for real-time performance.

Behavior Thresholds

  • Yaw/Pitch/Roll: Head movement sensitivity.
  • Suspicion Score: Overall alert trigger level.
  • Hand-Face / Hand-Object: Proximity detection thresholds.

Performance Controls

  • Render FPS: 15 / 30 / 60.
  • Frame Skipping: Keeps UI smooth on limited hardware.
  • Processing Interval: Fine-tune responsiveness vs. load.

Privacy & Retention

  • Auto-save Evidence: Store only suspicious events.
  • Retention: Automatic deletion after policy window.
  • Save Crops: Keep full frame and cropped evidence.

User Management

  1. Create proctor/admin accounts from Settings → Admin.
  2. Validation rules prevent duplicates and weak credentials.
  3. Only admins can manage users and reset passwords.

Warning: Deleting users is permanent.

Validation System

Live validation for secure account creation and data integrity.

What Gets Validated

  • Username: Minimum length, letters only, unique check.
  • Email: Valid format and duplicate prevention.
  • Password: Minimum length and strength rules.
  • Role: Controlled assignment (Proctor / Administrator).

Live Feedback

  • Inline hints show exactly what needs to be fixed.
  • Green status confirms valid inputs before submit.
  • Submission stays locked until all fields pass.

Security Notes

  • Passwords are stored as secure hashes.
  • User roles restrict access to settings and admin tools.
  • Validation prevents accidental duplicates.

Frequently Asked Questions

Common questions and answers.

Why do I see extra alerts?

Answer: Raise Suspicion Score or increase yaw/pitch thresholds in Settings → Detection.

Which YOLO model should I use?

Answer: Use small/medium for balance, large for maximum accuracy (GPU recommended), and nano for low-power devices.

Where is evidence stored?

Answer: Evidence is stored locally in output/history/cards/ and output/flagged_evidence/.

How long is data kept?

Answer: Retention defaults to 7 days (privacy policy). Admins can review policy in Settings → Privacy.

What if the system is slow?

Answer: Lower the model size, enable frame skipping, or reduce processing size.

Can I edit confirmed events?

Answer: Yes. Open the event in History and update the status with notes.
