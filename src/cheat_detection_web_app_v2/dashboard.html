System Help

Complete guide to using the Exam Cheat Detection System

Quick Start Guide

Get started with the system in just a few minutes!

What is this system?

The Exam Cheat Detection System is an AI-powered monitoring tool that helps proctors detect suspicious behavior during exams. It uses computer vision to analyze student behavior in real-time and alert proctors when something unusual is detected.

Step 1: Login

Access the system using your provided credentials. Proctors and administrators have different access levels.

If you don't have login credentials, contact your system administrator.

Step 2: Start Monitoring

  1. Navigate to the Monitor page from the sidebar
  2. Enter an exam name (e.g., "Math Final 2025")
  3. Click Start Pipeline
  4. Allow camera access when prompted

Step 3: Review Alerts

When suspicious behavior is detected, an alert appears on the right side of the screen. Click Review to:

  • See evidence image with detected behavior
  • Read the reason for the alert
  • Confirm or decline the alert
  • Enter student information

Step 4: View History

After your session, go to the History page to see all recorded events, filter them, and export evidence.

Pro Tip:

Adjust the detection sensitivity in Settings if you're getting too many or too few alerts.

Proctor User Guide

Complete guide for monitoring exams and managing alerts

Understanding the Monitor Page

The Monitor page is your main workspace. It has two main areas:

  • Left Panel: Live video feed showing what the camera sees
  • Right Panel: Alert queue showing pending suspicious behaviors

Starting & Stopping Sessions

To Start:

  1. Enter a descriptive exam name
  2. Click "Start Pipeline"
  3. Your webcam will activate and detection begins immediately
  4. Session timer starts automatically

To Stop:

  1. Click "Stop Pipeline"
  2. If there are pending alerts, you'll be warned
  3. You can review alerts even after stopping

Important: Always review all pending alerts before ending your session completely.

Understanding Alerts

Alerts are generated when the AI detects suspicious behavior. Each alert shows:

  • Evidence Image: Screenshot of what triggered the alert
  • Suspicion Score: How confident the AI is (0-100)
  • Timestamp: When it was detected
  • Reasons: What specific behaviors were detected

Common Alert Reasons:

  • Looking Away: Student turned their head significantly away from the Normal Base
  • Phone Usage Detected: A phone was detected near the student's hands
  • Hand Near Face: Student's hand is covering or near their face for an extended time
  • Suspicious Object Detected: Books, notes, or other prohibited items detected

Reviewing Alerts

  1. Click the alert card to open review modal
  2. Examine the evidence image (click to zoom)
  3. Read the detected behaviors
  4. Decide: Confirm or Decline
  5. If confirming, enter student ID and name
  6. Optionally add notes for context
  7. Click "Confirm Cheating" or "Decline"

You can decline an alert without entering student information, but confirmation requires student details.

Using the History Page

The History page shows all past events. You can:

  • Search by student name or ID
  • Filter by date range, event type, severity, or status
  • Click any event card to see timeline and evidence
  • Change status (confirm/decline pending events)
  • Export evidence for reports

Best Practices

  • Test before exams: Run a test session to ensure camera works properly
  • Adjust lighting: Ensure room has good, even lighting
  • Check camera angle: Position camera to clearly see students
  • Review promptly: Address alerts during or right after the exam
  • Document decisions: Use the notes field to explain your reasoning

Administrator Guide

Configuration and user management for administrators

Accessing Settings

Only users with the Administrator role can access the Settings page. Click Settings in the sidebar to open configuration options.

Detection Settings

Control how the AI detection works:

YOLO Model Size

  • Nano: Fastest, least accurate - use for low-powered devices
  • Small: Balanced speed and accuracy
  • Medium: Most accurate, slower - recommended for best results

Confidence Threshold

How confident the AI must be to detect objects (0.1 to 1.0). Lower = more detections but more false positives. Higher = fewer detections but might miss things.

Device Selection

  • CPU: Works on all computers, slower
  • GPU: Much faster, requires NVIDIA graphics card

Behavior Thresholds

Fine-tune what behaviors trigger alerts:

Yaw & Pitch Thresholds (Head Orientation)

How many degrees a student's head can turn before triggering an alert. Lower values = more sensitive.

  • Yaw: Left/right head turning
  • Pitch: Up/down head tilting

Suspicion Score Threshold

Overall score needed to create an alert (0-100). Recommended: 20-30 for most exams.

Hand-Face Distance

How close hands can be to the face before alert fires. Lower = more sensitive to phones near ears.

Hand-Object Distance

How close hands can be to suspicious objects. Lower = more sensitive to reaching for phones/books.

Performance Settings

Render FPS

How many frames per second to display (15/30/60). Higher = smoother video but uses more resources.

Frame Skipping

Skip processing some frames if system is slow. Helps maintain performance on slower computers.

Camera Settings

  • Resolution: 480p (fastest), 720p (recommended), 1080p (highest quality)
  • FPS: Camera frame rate (usually 30 FPS)
  • Camera Label: Custom name to identify this camera

Privacy Settings

Retention Period

How many days to keep event data before automatic deletion. Adjust based on your institution's policy.

Suspicion Save Threshold

Only save events above this score. Higher values = less storage used.

User Management (Admin Tab)

Add, edit, or remove user accounts:

Adding Users

  1. Click "Add New User"
  2. Enter username, email, and password
  3. Select role (Proctor or Administrator)
  4. Click "Create User"

Editing Users

Click the edit icon next to any user to update their information or change their password.

Deleting Users

Click the delete icon. This permanently removes the account.

Warning: Deleted users cannot be recovered. Make sure before deleting!

Saving Changes

Most settings are saved automatically when you change them. Look for the success confirmation message.

Technical Details

How the system works under the hood

System Architecture

The system uses a client-server architecture:

  • Frontend: Your web browser (HTML, CSS, JavaScript)
  • Backend: Flask server running AI models
  • Communication: Real-time WebSocket connection (Socket.IO)
  • Storage: Local JSON files for data persistence

AI Detection Pipeline

Each video frame goes through these steps:

1. Object Detection (YOLO)

YOLOv11 is a state-of-the-art computer vision model that detects:

  • People in the frame
  • Phones and electronic devices
  • Books and notebooks
  • Other suspicious objects

2. Pose Estimation (MediaPipe)

Google MediaPipe extracts 33 body landmarks to understand:

  • Where the head is facing (orientation)
  • Hand positions relative to face and objects
  • Body posture

3. Behavior Analysis

The system combined all detections to calculate:

  • Head Orientation Score: Is the person looking away?
  • Hand-Face Proximity: Are hands near the ears (phone use)?
  • Hand-Object Proximity: Are hands reaching for prohibited items?

4. Temporal Smoothing

Scores are averaged over multiple frames to reduce false alarms from quick movements.

5. Alert Generation

If the combined score exceeds the threshold, an alert is created with:

  • Screenshot evidence
  • Specific reasons
  • Confidence score
  • Timestamp

Technology Stack

  • Backend: Python, Flask, Flask-SocketIO
  • AI/ML: PyTorch, Ultralytics YOLO, MediaPipe
  • Computer Vision: OpenCV, NumPy
  • Frontend: HTML5, CSS3, Vanilla JavaScript
  • Real-time Communication: Socket.IO

Data Flow

  1. Browser captures webcam frame
  2. Frame sent to server via WebSocket
  3. Server runs AI detection pipeline
  4. Results sent back to browser
  5. Browser displays annotated frame and alerts
  6. Entire cycle completes in ~100-200ms

Privacy & Security

  • Only flagged events are saved to disk
  • Normal behavior frames are immediately discarded
  • All data stored locally (no cloud uploads)
  • Passwords are hashed using bcrypt
  • Session-based authentication

Performance Specs

  • Detection Latency: ~100-200ms per frame
  • Throughput: 5-10 FPS (depending on model and hardware)
  • RAM Usage: ~2-4 GB
  • GPU Required: recommended (NVIDIA CUDA)

Frequently Asked Questions

Why am I getting alerts for normal behavior?

Answer: The detection sensitivity might be too high. Go to Settings → Detection → Suspicion Score Threshold and increase the value to 25-30. You can also adjust the head orientation thresholds if students are being flagged for small head movements.

How accurate is the detection?

Answer: The AI achieves approximately 85-90% accuracy in detecting cheating behaviors under good conditions (proper lighting, clear camera view). Accuracy improves with the Medium YOLO model and decreases with Nano. Always verify alerts manually before confirming.

What camera should I use?

Answer: Any modern webcam (720p or higher) works well. Requirements:

  • Minimum 720p resolution (1080p recommended)
  • At least 15 FPS (30 FPS preferred)
  • USB or built-in laptop camera or CCTV
  • Clear view of students without obstructions

Can students see they're being monitored?

Answer: Students cannot see the detection system or alerts. This is a proctor-side tool only. However, you should inform students that AI monitoring is being used for fairness and transparency.

How do I reduce false alerts?

Answer: Try these steps:

  1. Increase the Suspicion Score Threshold to 25-35
  2. Increase Yaw and Pitch Thresholds to allow more head movement
  3. Ensure good, even lighting in the exam room
  4. Position camera to clearly see students without glare or shadows
  5. Use the Medium YOLO model for better accuracy

Where is evidence stored?

Answer: All evidence is stored locally on the server in the output/history/cards/ directory. Each student event has a separate folder containing:

  • Full frame screenshots
  • Cropped evidence images
  • Event metadata (JSON file)

How long is data kept?

Answer: By default, event data is retained for 7 days. Administrators can change this in Settings → Privacy → Retention Period. Data older than the retention period is automatically deleted.

The system is running slowly. What can I do?

Answer: Try these optimizations:

  • Switch to the Nano or Small YOLO model
  • Lower the camera resolution to 720p
  • Enable Frame Skipping in Performance settings
  • Close other applications to free up RAM
  • Use GPU instead of CPU if available

Can I monitor multiple exam rooms?

Answer: The current version supports one camera feed per instance. To monitor multiple rooms, you would need to run multiple instances of the system (one per computer/camera) or implement the multi-camera feature (future development).

What if I accidentally confirm the wrong alert?

Answer: Go to the History page, find the event card, open it, and you can change the status from confirmed to declined. Add a note explaining the correction.

Does this work on Mac/Linux?

Answer: Yes! The system is cross-platform and works on Windows, macOS, and Linux. All dependencies (Python, PyTorch, etc.) are available for all platforms.

I forgot my password. What do I do?

Answer: Contact your system administrator. They can reset your password through the Admin panel in Settings.
